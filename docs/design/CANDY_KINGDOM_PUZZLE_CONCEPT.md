## 2. パズル版の一文コンセプト

> **盤面を消すことが、そのまま魔法のお菓子をつくることになるパズル。**

補足すると、次の 3 つを**同じ 1 つの動き**に重ねる、という設計である。

| 遊びの動き | 世界観上の意味 |
| --- | --- |
| 行・列が消える | **材料が集まる** |
| COMBO が起きる | **錬成が起きる** |
| ステージをクリアする | **お菓子が完成し、国が戻る** |

**着せ替えにしない、というのはこの点である。**
ブロックを絵柄だけお菓子に差し替えるのではなく、
**すでに起きている盤面上の出来事に、そのまま目的の意味を割り当てる。**
新しい操作は増やさない（第 12 節）。

## 3. 想定プレイヤー

**根拠は [Phase 2C 人間評価結果](../evaluations/PHASE2C_HUMAN_EVALUATION.md) の実測である。**
想像ではなく、このゲームで実際に観測されたことから引いている。

| 観測（Phase 2C） | 設計への含意 |
| --- | --- |
| 説明カード（intro）は読み流された | **目的を文章で置かない** |
| ヒントより盤面を見て操作された | **目的を盤面の上に出す** |
| 短時間表示の文章は覚えられなかった | **常時見える場所に、絵と数で置く** |
| 文章が長いと読むのが面倒、という回答 | **UI に長文を置かない** |
| 待ち時間は「ちょうど良い」 | **尺を伸ばして解決しようとしない** |
| ①②・枠・矢印・KEEP 印・概念図に気づかなかった | **細い線・小さい記号に意味を載せない** |

主な想定：

- **短時間（1 ステージ 1〜3 分）で、落ち着いた 8×8 パズルを遊ぶ人。**
  操作の明快さと盤面の可読性が最優先（[開発方針](../DEVELOPMENT_POLICY.md) 第 2 節 Block Blast の長所）。
- 副次的に、**集める・図鑑が埋まる・国が戻るといった進行が動機になる人。**

**未検証：** この層が世界観を求めているかは調査していない。
「世界観を足せば続けてもらえる」は**仮説であって、根拠のある結論ではない。**

## 4. 1 プレイの基本ループ

図：[`ck-storyboard.webp`](assets/candy-kingdom-concept/ck-storyboard.webp)（6 コマ）

| # | プレイヤーがすること | 画面で起きること | 世界観上の意味 | 現行からの変更 |
| --- | --- | --- | --- | --- |
| 1 | 国に入る | 国の名前と、つくるお菓子の絵が出る | 依頼を受ける | **目標帯の中身のみ** |
| 2 | ピースをドラッグして置く | 現在とまったく同じ | 材料を並べる | **なし** |
| 3 | 行・列が揃う | 消える。**消えた色が目標の数字に入る** | 材料が集まる | 目標の判定と表示 |
| 4 | 連続で消える | CHAIN が進む | **魔法の熱が続く** | 表示の意味づけ |
| 5 | 特殊を組み合わせる | COMBO の光の中心に**お菓子が現れる** | **錬成** | 演出と報酬 |
| 6 | 目標を満たす | 勝利画面。図鑑 +1、国の回復ゲージが進む | お菓子が完成し、国が戻る | 報酬画面 |

**この 6 段のうち、操作が変わるのは 0 段である。**
プレイヤーの入力は「ピースをドラッグして置く」のままで、
変わるのは**盤面で起きたことに何の意味が割り当てられるか**だけである。

## 5. 長期的な進行ループ

| 層 | 内容 | 何がプレイヤーに残るか |
| --- | --- | --- |
| 1 ステージ | 材料を集める → お菓子を 1 つ完成させる | スコア、手数の余り |
| 1 つの国（複数ステージ） | その国のお菓子をそろえる | **国の回復**（背景の絵が変わる） |
| 図鑑 | 完成したお菓子が 1 つずつ増える | **収集の記録** |
| キャラクター | 国ごとの住人との関係が進む | **戻ってくる理由** |
| 12 の国全体 | 国が順に開く | **全体の進行** |
| 特別ステージ | 盤面の雰囲気とルールが変わる | **変化** |

**この構造には未検証の前提が 3 つある。**

1. 「国が戻る」ことがプレイヤーにとって報酬になるか — **未検証**
2. 図鑑が埋まることが継続動機になるか — **未検証**
3. 12 という数が長すぎないか — **未検証**

いずれも人間確認（第 14 節）で確かめる項目であり、この文書では決めない。

## 6. P1 〜 P3 の具体例と評価

**P1 〜 P3 は別ゲーム案ではない。同じパズルゲームの中の「ステージ目標の型」の候補である。**
現行のステージデータはすでに `objectives` を**配列**で持っているため、
**1 つのステージが複数の型を同時に持つことも、型ごとにステージを分けることもできる。**

図：[`ck-goal-types.webp`](assets/candy-kingdom-concept/ck-goal-types.webp)（3 案の目標表示を同一条件で比較）

**最初から 3 種類すべてを採用するとは決めない。**

### 6-1. P1：レシピ収集型

行や列を消して必要な色・材料を集め、指定された魔法のお菓子を完成させる。

**具体例**

| 例 | 目標表示（文章なし） | 内部の判定 |
| --- | --- | --- |
| 赤 8 個・黄 6 個で「たいようキャンディ」 | ☀ たいようキャンディ ／ 🔴 6/8 ・ ⭐ 4/6 | 消えたセルの色を数える |
| 青と紫で「ほしぞらゼリー」 | 星のアイコン ／ 🔷 3/6 ・ ◆ 2/6 | 同上 |
| 指定手数以内に 3 種類 | お菓子の絵 ／ 3 色のチップ ＋ MOVES | 同上 ＋ 既存の手数 |

**長所**

- **消去と収集が同じ動きになる。** 行が消えた瞬間に数字が増えるので、
  因果が 1 フレームで見える。Phase 2C の未達（「何が起きたか説明できない」）の逆をいく構造。
- **絵と数字だけで目標が成立する。** 文章が要らない（第 3 節の観測に最も素直に応える）。
- **実装負荷が最も小さい**（第 12 節）。
- **難度を数で調整できる。** 8 個 → 12 個で素直に難しくなる。

**弱点**

- **Block Blast との差が最も小さい。** 「色を集める」は多くの落ちものパズルにある形で、
  これだけでは世界観が**着せ替えに留まる危険がある。**
- **色に依存する。** 色覚特性のあるプレイヤーには不利になりやすい。
  形の冗長手がかり（第 11 節）と、目標チップにブロックと同じ刻印を出すことで補うが、**未検証**。
- **盤面を見ずに目標帯だけ見て遊べてしまう可能性。** Phase 2C の E-06（読まなくても遊べる）と同型の risk。

**初見理解のしやすさ：高い**（絵 ＋ 数字 ＋ 増える動き）。ただし**未検証**。

### 6-2. P2：魔法陣・形状完成型

盤面上で指定された形・位置・囲み方を完成させ、魔法のお菓子を錬成する。

**具体例**

| 例 | 盤面での見せ方 | 内部の判定 |
| --- | --- | --- |
| 中央の錬成核を囲む | 核の周囲 8 セルを点線で表示、埋まるたび実線化 | 指定 index が埋まったか |
| 十字形を完成させる | 十字の形を薄く重ねて表示 | 同上 |
| 特殊を指定の場所へ運ぶ | 目的地セルを光らせる | 特殊の index を照合 |
| 空けておくセルを守る | **別の記号**で保護セルを表示 | 埋まったら失敗 |

**長所**

- **[開発方針](../DEVELOPMENT_POLICY.md) 第 2 節の Block Blast の長所（空間を考えて配置する）と最も相性がよい。**
  「どこに置くか」がそのまま目標になる。
- **目標が盤面の上にある。** 目標帯を見なくても遊べる ＝ 第 3 節の観測（盤面しか見ない）に構造で応える。
- **色に依存しない。** 色覚特性の影響を受けにくい。
- 「魔法陣を閉じる」という絵が、世界観と最も直結する。

**弱点（説明なしで理解できるかが最大の論点）**

- **「ここに置く」と「ここを空けておく」は正反対の意味なのに、どちらも枠で示すことになる。**
  Phase 2C では**細い枠・小さい記号は気づかれなかった**（D-01 / E-06）。
  **同じ視覚言語で反対の意味を出すのは、この評価結果に照らして危険である。**
  記号を分ける設計が必要だが、**本ラウンドでは設計していない。**
- **誤って埋めると失敗する型は、理不尽に感じられやすい。** 取り返しのつかない一手が生まれる。
- **難度設計が難しい。** ピースはランダムに来るため、「その形を作れるピースが来ない」が起こりうる。
- 実装負荷が 3 案で最も大きい（第 12 節）。

**初見理解のしやすさ：中〜低。** モック（[`ck-goal-types.webp`](assets/candy-kingdom-concept/ck-goal-types.webp) 中央）では
点線の 8 セルと金色の核で示したが、**これが「囲め」と読めるかは未検証。**

### 6-3. P3：特殊錬成型

ROCKET / BOMB / COLOR BLAST を生成・保持・組み合わせて、特別なお菓子を錬成する。

**具体例**

| 例 | 目標表示 | 内部の判定 |
| --- | --- | --- |
| ROCKET＋BOMB で「にじのマカロン」 | 🚀 ＋ 💣 → マカロンの絵 ／ 0/1 | **既存の `combo` 目的（`effect: 'rocket+bomb'`）でそのまま表せる** |
| BOMB を残したまま材料を集める | マカロンの絵 ＋ 色チップ（P1 と併記） | 既存の複数 objective |
| 特殊 2 個を指定の順序で起爆 | ① 🚀 → ② 💣 | **順序の判定は新規** |

図：[`ck-alchemy-before-after.webp`](assets/candy-kingdom-concept/ck-alchemy-before-after.webp)（前・瞬間・完成の 3 コマ）

**長所**

- **Phase 2C の最大の未達に、直接あたる。**
  Phase 2C では「**BOMB を残す意図が理解されなかった**」「**COMBO を狙う理由が伝わらなかった**」。
  P3 はこれに「**お菓子の材料だから残す**」という**目的そのもの**を与える。
- **目標表示が「🚀 ＋ 💣 → 🍬」という絵の式になる。**
  文章「ROCKET と BOMB を 同時に 起爆」を、**絵に置き換えられる**
  （[`ck-vs-current.webp`](assets/candy-kingdom-concept/ck-vs-current.webp) 左右で比較）。
- **COMBO の光がそのままお菓子の形に変わる**演出が作れる。
  Phase 2C の「演出の後で読ませる」構造（監査 D-01）を、
  **演出そのものが答えになる**構造へ変えられる可能性がある。

**弱点**

- **特殊が出ないと進まない ＝ 運の要素が入る。** 手数制限と噛み合うと理不尽になる。
- **初心者ステージには使えない。** 特殊の生成規則を理解している前提がある。
- **「物語上の目的が付けば理解される」という保証はない。**
  Phase 2C は「文章が読まれない → 動きで見せる」と対処して未達だった。
  **「動きが分からない → 目的を付ける」も同じ形の推測である。**
  これは**検証すべき仮説であって、結論ではない。**

**初見理解のしやすさ：低〜中。** ただし**絵の式が文章より強いかは未検証。**

| 品質軸（方針文書 第 2 節） | 本案の立場 |
| --- | --- |
| 盤面が一目で読める | **維持する。**第 4 ラウンドの計測値を落とさない（第 11 節で実測） |
| 置ける／置けないの判断のしやすさ | **維持する。**操作は変えない |
| 演出を増やしても盤面認識を阻害しない | **維持する。**遮蔽率は第 4 ラウンドと同値のまま |
| 完成度・情報密度・反応・報酬の見せ方 | 報酬画面を新設して応える（第 12 節） |

**差別化として意図している点**

- **消去が目的そのものではなく、目的（お菓子）への手段になる。**
  一般的な同種のパズルでは「消す」ことが得点であり終点だが、本案では
  「消す」→「材料が集まる」→「お菓子ができる」→「国が戻る」という**段が付く。**
- **特殊ブロックを「使う」だけでなく「残す」動機が、遊びの外側（物語）から与えられる。**

**差別化できているかは未検証である。**
比較対象の実物を確認していない以上、「他と違う」と断定はできない。
言えるのは「**この 3 段構造を、現在の BLAST BLOCK は持っていない**」ということだけである。

**用語の暗記ではなく、操作の結果として理解できる形にする**

**重要な限定：**
CHAIN と COMBO の意味づけを変えることは、**Phase 2C の誤認が直る保証にはならない。**
Phase 2C は「別の板・別の色で表示する」という対処をして未達だった。
**意味づけの変更もまた対処案の 1 つであって、効果は人間評価でしか確かめられない。**

なお、**CHAIN と COMBO が同一フレームで同時に出る**という監査の指摘（D-04、実測 t=911ms）は、
**世界観を載せても解決しない。** これは表示タイミングの問題であり、第 5 手順（縦切り実装）で扱う。

#### 結果：第 4 ラウンドで見つかった形の問題が解消した

[デザイン方向案 48 節](MAIN_PLAY_DESIGN_DIRECTIONS.md) で、
**◆●▲■✚ のうち ●（丸）と ■（四角）の刻印が 85% 重なっている**（相違度 15%）ことが判明し、
2B へ持ち越しになっていた。**お菓子の意匠にした結果、この問題は解消した。**

| 組み合わせ | 第 4 ラウンド ◆●▲■✚ | **構想試作（お菓子）** |
| --- | --- | --- |

| ◆ purple vs ● red | 22% | 46% |

| ▲ blue vs ■ green | 39% | 41% |
| ◆ purple vs ▲ blue | 46% | 43% |
| ▲ blue vs ✚/★ yellow | 55% | 45% |
| ■ green vs ✚/★ yellow | 48% | 50% |
| ● red vs ✚/★ yellow | 41% | 61% |
| ● red vs ▲ blue | 39% | 63% |
| **最小** | **15%（NG）** | **37%（OK）** |

測り方は 48 節と同じ（刻印あり／なしの差分マスクの対称差 ÷ 和集合、下限 35%、セル 35px＝320px 幅）。
セル 46px（393px 幅）でも最小 38% で下限を満たす。

**ただし代償がある。**
お菓子の意匠は刻印がブロック面を広く覆うため、**ブロックの「中央どうし」のコントラストが下がった。**

| 指標 | 第 4 ラウンド | **構想試作** |
| --- | --- | --- |
| ブロック面 / 隣のセル（**刻印を避けた面**） | 1.67 / 1.51 | **1.44 / 1.49**（下限 1.30 → OK） |
| **刻印の中心どうし**（参考） | 1.67 / 1.51 | **1.21 / 1.31** |

（左が A2-HW-R、右が N1）

**識別規則が対象にしているのは「面」のコントラストであり、そちらは下限を満たしている。**
とはいえ中央の余裕が減ったのは事実で、**刻印の白いハイライトを 0.75 → 0.50 に下げて調整した**
（0.75 のままだと 1.15 / 1.25 まで落ちた）。
**さらに詰めるなら刻印を小さくする必要があるが、そうすると形の相違度が下がる。**
このトレードオフの最終調整は **2B（第 4 手順）で行う。**

## 15. 未検証・未調査

| 区分 | 内容 |
| --- | --- |
| **人間にしか判定できない** | 着せ替えに見えないか／目標が絵で伝わるか／お菓子ブロックの見分けやすさ／報酬が嬉しいか／12 国の長さ／仮称の可否 |
| **実装しないと分からない** | 錬成演出の実機負荷、目標オーバーレイと盤面の干渉、P2 の難度、運の影響 |
| **調査していない** | **永続保存（セーブ）の仕組みの有無**（第 12-3 節）、想定プレイヤー層が世界観を求めているか |
| **方法上の限界** | 形の相違度は輝度差 10 以上を刻印とみなす二値マスクの比較であり、人間の形の弁別能力そのものではない |
| **引き継ぎ** | 監査 D-04（CHAIN と COMBO が同一フレームで出る）は世界観では解決しない。第 5 手順で扱う |

**Toon Blast / Block Blast の実物は確認していない。**
本文の言及はすべて [開発方針](../DEVELOPMENT_POLICY.md) 第 2 節で定義された品質軸との比較である。
**規格適合の主張もしていない。** 4.5 / 1.30 などの下限は本プロジェクト内の基準として使っている。
