## 2. 登録原本の背景に関する決定

### 2-1. 決定

**登録原本を本番の白地・黒地・カード背景へ直接配置することを禁止する。**【確】

**灰色背景の削除や単純な色選択による透過化も採用しない。**【確】
輪郭に灰色の縁（フリンジ）が残るためである。

### 2-2. 根拠（実測）

登録原本は**全画素 α＝255**（世界観 12-2 の共通仕様）で、透明度を持たない。【確】
背景と接する非背景画素が `#808080` からどれだけ離れているかを測った結果：【確】

| 原本 | 輪郭画素 | 平均 \|Δ\| | \|Δ\| ≤ 12 の割合 |
| --- | --- | --- | --- |
| ヴェスタ v2 | 5,782 | 2.66 | **98.2%** |
| カイエ v3 | 9,213 | 3.39 | **97.4%** |
| リヴェル v3 | 5,859 | 3.75 | **96.9%** |
| ネイ 正面 v2 | 7,542 | 2.42 | **96.6%** |

### 2-3. 本番人物画像の作り方

**登録ラフを造形参照として、透明背景と本番表示寸法を前提に、制作側が別ファイルとして制作する。**【確】

### 3-4. 刻印の大きさと白ハイライト

**2A には刻印の寸法の実測値がない。**現行のグレーボックス実装にも刻印は入っていない
（`src/ui/` に刻印を描くコードはない）。
**2026-09-15 に、利用者が比較画像を目視して以下を 2B 最終候補として確定した**（根拠は 3-14）。

| 項目 | 2B 最終候補 | 理由 |
| --- | --- | --- |
| 刻印の描き方 | **中空**（輪郭線のみ。面を塗りつぶさない） | 5 形総当たりの最小相違度が塗り 43.5% に対し中空 53.1%（セル 35px）。人間目視でも 35px・46px の両方で 5 形を判別できた（3-14-4） |
| 刻印の外接 | **セル寸法の 50%** | 35px で 17.5px、46px で 23px。50% での実測が 3-14 の根拠値。**46% ではない**（初版の推奨値から変更） |
| 刻印の線幅 | **セル寸法の 7%**（最小 2px） | 31px で 2.17px、33px で 2.31px、35px で 2.45px、46px で 3.22px。1px では 3 倍表示以外で消える |
| 確認済みのセル寸法 | **31 / 33 / 35 / 46px**（2026-09-15 に追加確認） | **320×568 の実寸は 33px（目標 1 件）と 31px（目標 2 件）**であり、35px ではない。4 サイズすべてで下限 40% を満たす（3-15-2） |
| 刻印の色 | **ブロック面と同色相で `(Y+0.05)×1.35−0.05` まで持ち上げた色。色相を保ったまま届かない場合（blue・yellow）のみ白を混ぜる** | 白一色にすると legal preview（`#ffffff`）と競合する |
| 刻印とブロック面の輝度差 | **1.35 以上** | 2A 48 節は「輝度差 10 以上を刻印とみなす」で測っている。1.35 はその二値化に確実に載る値。実レンダの実測は 1.3527〜1.3597（3-14-6） |
| 白ハイライト | **ブロック上端 1 本、セル寸法の 6% の高さ、不透明度 0.35** | 立体感を出しつつ、 `#ffffff` の legal preview と混同させないため**面全体には広げない** |
| 白ハイライトを出さないもの | **特殊ブロック** | 初版の理由「本体が `#f6f8fa` で白に近い」は、特殊の面を `#7a8f98` へ変えた（3-15-3）ので成り立たない。**特殊に白ハイライトを出すかどうかは未確定**（3-15-9） |

**【要】** 刻印が「うるさい」か「足りない」かは実画面でしか判定できない。
2A 51-2 は A2-HW-R について「虹色感と華やかさが**弱すぎると判断される可能性**」を挙げている。
**盤面のエッジ量について**：2A 45 節の **3.84** は測定方法（カーネル・色空間・正規化）が
記録されていないため、**今回のハーネスの数値と直接比較できない。**
**3.84 を今回の別方式の数値へ置き換えない。**刻印がエッジ量へ与える影響は、
同一ハーネス内の「刻印なし → 塗り → 中空」の増加量として 3-14-7 に記録した。

### 3-7. ● と ■ の冗長な識別（2B で必ず解決する 1 件目）

**測定（2026-09-15）**【確】

**2A には刻印の寸法が保存されていない。**したがってこの測定は、

比べられるのは、**同じ幾何のなかでの現状・案A・案B の差だけ**である。

| 組 | 現状 | 案A（● を ◎ へ） | 案B（■ を ⬢ へ） |

  12.7% → 39.8% と大きく改善する。

**未確定**【要】

- **案A でも 5 形の総当たりの最小は 17.0%（35px）にしかならない。**

- ◆ の縦横比または角度

**残す回帰検査**（2026-09-15 に測定定義を確定した）

実装後に、**トークン値ではなく実際のレンダリング結果**を測る。

**判定対象＝面平均。**【2B 最終候補として確定】

| 項目 | 定義 |
| --- | --- |
| 面領域 | `Mface − Mglyph − Mhi` |
| `Mface` | ブロックのシルエット（角丸矩形、インセット込み）を**縁幅 + 1px ぶん収縮**した領域 |
| `Mglyph` | 刻印だけを描いたマスクを **1px 膨張**した領域 |
| `Mhi` | 上端ハイライト帯 |
| 測定値 | 面領域の**線形 RGB 相対輝度の算術平均** |
| 情報表示 | 平均に加えて **5%点・中央値・95%点**も残す（合否には使わない） |
| 測定単位 | Canvas の**原寸** `getImageData`。ブラウザの拡大縮小を挟まない |

| # | 検査 | 下限 |
| --- | --- | --- |
| 1 | 黄ブロック / 隣接する空きセル（grayscale 後） | **1.30 以上** |
| 2 | 通常時の 5 色総当たりの最小（面平均） | **1.50 以上** |
| 3 | protan / deutan / tritan の 5 色総当たりの最小（Viénot を線形 RGB へ。面平均） | 各 **1.20 以上** |
| 4 | 空きセルの縁 / セル面（**実レンダリング画素**。面平均とは別条件） | **1.30 以上** |
| 5 | 盤面の中 / 盤面の外 | **1.30 以上** |

**縦に隣接する「上セルの最暗画素 / 下セルの最明画素」を合否条件にしない。**【確】
**理由**：実際の盤面では、隣り合う 2 つの**面が直接接することがない。**
面と面のあいだには必ず**面インセット 4% × 2 ＋ ブロック縁 8% × 2 ＝ セル寸法の 24%**
（セル 35px で 8.4px）が入り、その区間は縁色である。
縁は面に対して 1.71〜3.18、grayscale 後でも 1.31 以上（3-14-3）。
したがってこの 2 画素の比較は、**実際には接していない 2 画素を仮想的に並べた条件**であり、
面全体の識別性を代表しない。**参考値としてのみ記録する。**

**「縁があるから面色の不足を無条件に許す」という意味ではない。**
**検査 2・3（面平均）と検査 4（縁 / 面）は、それぞれ独立に満たす必要がある。**

検査する画面には次を**すべて含める。**トークン値だけで判定しない。

- グラデーション
- 刻印
- 縁
- ハイライト
- 影
- **特殊ブロックの発光あり／なしの両方**

測定のたびに、3-13 の再発防止の 7 項目を残す。

#### 3-14-6. 面グラデーション（2B 最終候補）

**`a = 0.04`。線形 Y を上端 ×1.04、下端 ×0.96。**

| a | 横隣接 通常 | protan | deutan | tritan |
| --- | --- | --- | --- | --- |
| 0.00 | 1.5501 | 1.2432 | 1.2843 | 1.2234 |
| 0.02 | 1.5485 | 1.2374 | 1.2787 | 1.2103 |
| **0.04** | **1.5475** | **1.2411** | **1.2789** | **1.2092** |
| 0.06 | 1.5420 | 1.2356 | 1.2709 | 1.2036 |
| 0.08 | 1.5407 | 1.2326 | 1.2774 | **1.1949**（下限割れ） |
| 0.10 | 1.5290 | 1.2311 | 1.2841 | 1.1807 |
| 0.13 | 1.5189 | 1.2311 | 1.2722 | 1.1802 |

**a = 0.06 ではなく 0.04 を採る理由**

- a=0.06 の横隣接 tritan は 1.2036 で、下限 1.20 までの余裕が小さい。
- a=0.04 なら tritan 1.2092 で、8bit 丸め・実装差・グラデーション位置の差への余裕が増える。
- a=0.08 では実際に 1.1949 まで下がる。
- A2-HW-R は盤面を画面内で静かに保つ必要があり、強いグラデーションを優先する理由がない。

**a = 0 にはしない。**上端ハイライトと穏やかな面変化を残す。

**刻印 / 面 の輝度比（a=0.04 の実レンダ、セル 35px）**：
purple 1.3574 ／ red 1.3597 ／ blue 1.3557 ／ green 1.3595 ／ yellow 1.3535。
いずれも下限 1.35 を満たす。
blue と yellow は**色相を保ったままでは (Y+0.05)×1.35−0.05 に届かない**ため、
白を混ぜて輝度を上げている（3-4）。

#### 3-14-7. 盤面エッジ量

**測定方法**：盤面の 8×8 セル領域のみ（外枠を除く）。
CSS `filter: grayscale(1)` と同じガンマ域の輝度加重でグレー化し、
(a) 前方差分 `sqrt(dx²+dy²)` の平均、(b) Sobel 3×3 の勾配強度 ÷8 の平均。

**2A 45 節の 3.84 / 4.19 とは測定方法が一致しない。**
2A は「局所勾配の平均」としか書いておらず、カーネル・色空間・正規化の記載がない。
**絶対値を直接比較しない。3.84 を今回の別方式の数値へ置き換えない。**
**主結果は同一ハーネス内の「刻印なし → 塗り → 中空」の増加量とする。**

| セル | 測り方 | 刻印なし | 塗り | 中空 | 中空 − 塗り |
| --- | --- | --- | --- | --- | --- |
| 35px | 前方差分 | 22.211 | 23.225（+4.56%） | 23.620（+6.34%） | **+1.70%** |
| 35px | Sobel | 20.469 | 21.447（+4.78%） | 21.766（+6.33%） | **+1.49%** |

**結論**

- 中空は塗りよりエッジ量がわずかに増える。増加は **1.5〜1.8%**。

#### 3-14-8. 測定条件の宣言（3-13 の再発防止 7 項目に対応）

1. **対象**：一時領域で生成した Canvas。3-14-1 の 3 枚が目視資料。
   外部の保存画像を測っていない。バイト数・寸法・SHA-256 は 3-14-1 に記載。

   5%点・中央値・95%点・最小・最大も併記する（3-14-2）。
4. **色変換式と適用先**：コントラストは sRGB を線形化した相対輝度。
   色覚変換は **Viénot / Brettel–Mollon (1999) の LMS 射影を線形 RGB へ**適用。

   特殊ブロックは発光なしの状態のみ描画している（**発光ありは未測定**）。
6. **CSS 寸法と実ラスタ寸法**：`deviceScaleFactor = 1`、Canvas の**原寸** `getImageData`。
   ブラウザの拡大縮小を挟んでいない。比較画像内の拡大は最近傍で、測定には使っていない。
7. **再現できない値を合否条件に使わない**：2A 45 節の 3.84 は方法が記録されていないため、
   **合否条件として使わない**（3-14-7）。

#### 3-17-2. 音の方向【確】

**「結晶が触れ合い、灯がともる音」。**
石造りの静かな場所で、水晶が軽く触れ、細い光が立ちのぼるような音。
厚みではなく**透明さと立ち上がりの速さ**で情報を伝える。

**採用してよい音色**：ガラス／水晶／淡い鐘／短い空気音／柔らかい石または木の接触／
複数音が和音へまとまる表現。

**使わないもの**：爆発／銃声／警報／強いブザー／硬いコイン音／長いファンファーレ／
コミカルな玩具音／罰を強調する下降音。

| 対象 | 音の性格 |
| --- | --- |
| 通常ブロック | 軽く、短く、乾いている。水晶どうしが触れる「こつ」 |
| 通常消去 | 息を抜くような開放。結晶がほどけて散る |
| 特殊 | 通常より一段、芯がある。内側に小さな共鳴を持つ |
| COMBO | 盤面で最も重要。複数の音が**和音へまとまる**。散らばらない |
| CHAIN | 音量ではなく**音高と密度**で段を示す |
| 目標達成 | 静かな確定。淡い鐘が 1 つ |
| 勝利 | **失われた灯が戻る。**祝祭ではなく回復。上昇 → 収束 → 着地 |
| 失敗 | 静かに息を止める。罰も嘲笑もしない |
| 置けない | 無機質な小さな遮り。否定ではなく「ここではない」 |

#### 3-17-5. 時間軸との接続（3-16-5 の案 S へ接続）

| 問い | 決定 | 理由 |
| --- | --- | --- |
| 通常消去音を 90ms と 220ms のどちらで始めるか | **220ms** | 配置音が 0〜90ms を占め、90ms に始めると 2 音が直に接して 1 つの濁った音になる。220ms なら 130ms 離れ「置いた → 消えた」の 2 拍に読める。ライン強調 90〜220ms には**音を付けない** |
| 特殊生成音を 220ms に始めるか | **はい** | 局所暗転の開始と同一フレーム |
| 特殊起爆音をフラッシュ開始 220ms に合わせるか | **はい** | フラッシュ開始と同一フレーム |
| COMBO 音の主音を核と同時に始めるか | **はい、220ms** | 核の開始と同一フレーム。**主音は 1 つだけ** |
| 目標達成音を 220ms と 460ms のどちらへ置くか | **460ms** | 220ms は消去・特殊生成・COMBO と衝突する最も混んだ時刻。460ms は進捗が満ちきって達成が視覚的に確定する瞬間 |
| 勝利音を 1 音にするか 3 段にするか | **3 段（3 ファイル）** | 1 音では 620ms の金と 780ms のカードが無音になり、3-16-2 の因果が音で追えない |
| 失敗音を 90ms と 210ms のどちらへ置くか | **90ms** | 暗転の開始が失敗の最初の視覚。210ms に置くと暗転の 120ms が無音になる |

**1 イベントへ不要に複数の音を重ねない。**
複数段になるのは**勝利のみ**で、**複数ファイル**（`win-a` / `win-b` / `win-c`）である。
**1 ファイル内の複数段は使わない。**識別レイヤーは「段」ではなく「重ね」である。

#### 3-17-6. 優先度・ダッキング・同時発音

| 優先度 | イベント | ダッキング対象 | 量 |
| --- | --- | --- | --- |
| **100** | COMBO | 他のすべての効果音 | −9 dB（40ms / 保持 200ms / 解放 180ms） |
| **95** | 勝利 | 盤面効果音すべて＋**以降の新規発火を停止** | −12 dB（460ms） |
| **90** | 失敗 | 直前の配置音・消去音を 80ms でフェードアウト | 停止 |
| **80** | 特殊起爆 | 通常配置・通常消去 | −9 dB（40ms） |
| **70** | 特殊生成 | 通常消去 | −9 dB（40ms） |
| **60** | CHAIN | なし | — |
| **55** | 目標達成 | なし | — |
| **40** | 通常消去 | なし | — |
| **20** | 通常配置 | なし | — |
| **15** | 置けない | なし | — |

**同時発音の上限：効果音バス全体で 8 ボイス。**
上限に達したら**優先度の最も低い再生中のボイスを 40ms でフェードアウトして奪う。**
同一ファイルの重複は**常にボイススティール**で 1 本に保つ。

**規則**

- 同一フレームで複数発火したら、**優先順位が最も高いものだけを鳴らす**（2A 11 節）。
- **CHAIN は段数が上がっても音量を無制限に上げない**（上限 −9.5 dB、CHAIN2 比 +2.5 dB）。
- **COMBO 時は通常消去音を −9 dB まで抑える。**消さない（消去が起きたことが音で追えなくなる）。
- **勝利開始後（460ms）は盤面効果音を −12 dB へ減衰し、新規発火を停止する。**
- **結果オーバーレイ表示後（勝利 980ms / 失敗 410ms）は残響を 400ms まで許容。**超える尾は切る。
- **失敗時は直前の配置音・消去音を 80ms でフェードアウト**して、失敗音の前を静かにする。

**具体例 A〜F**

| 例 | 状況 | 鳴らす | 抑える | 鳴らさない |
| --- | --- | --- | --- | --- |
| **A** | 通常消去 ＋ 特殊生成（どちらも 220ms） | **特殊生成音（70）**＋識別レイヤー | — | **通常消去音（40）。**消去の質感は `special-create` の素材へ含めて制作する |
| **B** | 特殊起爆 ＋ COMBO（どちらも 220ms） | **COMBO 音（100）**＋識別レイヤー最大 2 | — | **特殊起爆音（80）。**COMBO は起爆の上位事象なので二重に鳴らさない |
| **C** | COMBO（220ms）＋ CHAIN 2（460ms） | **両方**（時刻が違う） | COMBO のダッキングは 460ms から解放が始まるので、CHAIN は −9 dB の尾を受けて立ち上がる | — |
| **D** | 目標達成 ＋ 勝利（どちらも 460ms） | **勝利 a（95）** | — | **目標達成音（55）。**最終目標の達成は勝利音へ吸収。最終でない目標は通常どおり鳴る |
| **E** | 置けない操作の連打 | 最初の 1 回、以後 **180ms 以上あいた発火のみ**。1 秒に最大 3 回 | — | 4 回目以降。**600ms 無音が続くまで抑制**し、抑制中はカウンタを進めない |
| **F** | 複数特殊が同一 wave で起爆 | **効果セル数が最大の 1 グループのみ**（同数なら `index` 昇順）。識別レイヤーは最大 2 枚 | — | **2 つ目以降のグループの音** |

#### 3-17-7. CHAIN の仕様

| 項目 | 値 |
| --- | --- |
| 素材 | **同じ素材 1 本をピッチ変更**（段数ごとの別素材は作らない） |
| ピッチ | CHAIN2 ×1.000 ／ CHAIN3 ×1.122（+2 半音）／ **CHAIN4 以上 ×1.260（+4 半音）で頭打ち** |
| 音量 | CHAIN2 −12.0 dB ／ CHAIN3 −10.5 dB ／ **CHAIN4 以上 −9.5 dB で頭打ち**（上昇は合計 +2.5 dB まで） |
| 4 以上の扱い | **同一扱い**（ピッチも音量も CHAIN4 の値で固定） |
| 高速連鎖で重なった場合 | **ボイススティール。**前を 60ms でフェードアウトして置き換える。重ねない |
| 外周演出との同期 | **外周 200ms の開始と同一フレームで発音**（案 S では後続 wave の開始 460ms） |
| 聴覚過敏への配慮 | ピッチ上限 +4 半音。音量上限 −9.5 dB。トゥルーピーク −5.0 dBFS を超えない。 **4 段目以降で無限に上がらないことを自動検査で確認する** |

**無制限に高音・大音量へ上がる設計を禁止する。**

**ページ非表示（`visibilitychange`）と `AudioContext`**【確】

**現在このハンドラは存在しないので新設する。**

- `hidden` で**再生中の音を短くフェードアウト**する。
- その後 **`AudioContext.suspend()` を試みる。**
- `visible` で **`resume()` を試みる。**
- **ブラウザが利用者操作を要求して resume できない場合は例外にせず、
  次の pointer 操作で resume する。**
- **復帰失敗中もゲームロジックは止めない。**
- **復帰時に、非表示中に発火した過去の音をまとめて再生しない。**
- **勝利・失敗の途中で非表示になった場合も、復帰時に音を途中から再開しない。**
- **視覚状態だけを現在時点へ同期する。**

**端末のサイレント設定との関係**【確】

**Web ゲームの音が端末のサイレント設定へ必ず従うことを、2B の保証事項にしない。**
ブラウザと OS の挙動へ依存するため、**ハードウェアのサイレント設定だけに頼らない。**

- **ゲーム内に明示的なミュートを設ける。**
- 初回既定値は **master 0.6**。
- **初回の音声開始前に利用者の操作を必要とする。**
- **実際の iPhone Safari で、サイレントモード ON / OFF の両方を手順 5 で確認する**（5-3）。
- **「サイレントモードで必ず鳴る」「必ず消える」のどちらも現時点で保証しない。**
- **端末の制限を回避する無音再生などのハックは使わない。**

**BGM の扱い**【確】

**今回の制作対象へ含めない。**

1. **手順 5 では効果音だけで認知と同期を検証する。**BGM は画面全体の印象を支配し、
   「特殊・COMBO・CHAIN に気づけるか」という Phase 2C 由来の検証を汚す。
2. Phase 2C の未達は「演出に気づかなかった」であり、**効果音の不在が直接の原因**。
3. BGM は尺・ループ点・遷移・ダッキングという**別規模の設計**を要する。
4. 容量とデコードコスト。

**内部の `music` バス予約だけは行う。**
**BGM 素材・ループ・遷移・ダッキングは今回設計しない。**
**BGM が存在しない段階では、利用者向けの「BGM 音量スライダー」を表示しない。**

| 登録する値 | **SHA-256・バイト数・実時間（ms）・サンプルレート・チャンネル数・ トゥルーピーク・サンプルピーク・DC オフセット・active-region RMS** |
| 無音区間の上限 | 末尾の無音 **≤ 30ms**。中間の完全無音 **≤ 20ms** |
| 先頭パディングの上限 | **≤ 2ms**（48 kHz で 96 サンプル）。**これが WAV を選ぶ最大の理由** |

**読み込みの 4 状態**【確】

**「プリロード」という語が取得・デコード・`AudioContext` 開始を混同しないよう、
次の 4 つを別の状態として扱う。**

| # | 状態 | 内容 |
| --- | --- | --- |
| 1 | **fetch** | ファイルの取得。**ゲーム起動後に開始してよい**（利用者操作を待たない） |
| 2 | **decode** | `decodeAudioData`。fetch 完了後 |
| 3 | **AudioContext unlock** | `AudioContext` の生成と `resume`。**最初の利用者操作後** |
| 4 | **playback ready** | 1〜3 がそろって初めて「再生準備完了」 |

**15 本すべてを同じ資産群として準備する理由**

- 合計上限 **800 KB** で十分小さい（最大長で見積もっても約 516 KB）。
- **目標が 1 件だけのステージでは「最終目標の 1 つ前」の時点が曖昧**である。
- **回線状態によって勝利音だけ間に合わない危険**を避ける。
- **勝利は最も欠落させたくないイベントの 1 つ**である。

**読み込みの規則**

- **15 本すべてについて、手順 5 開始時の縦切り検証で「再生準備完了／失敗」を追跡する。**
- **未準備の音があってもゲームを停止しない。**
- **勝利へ到達した時点で未準備なら無音で続行し、例外を投げない。**
- **読み込み失敗を自動再試行し続けない。**
- **デバッグ表示に未準備数だけを出す。**

**全ファイルをモノラルへ統一した理由**【確】

- iPhone の小型スピーカーで**定位差を主要情報に使わない。**
- **左右差をアクセシビリティ条件にしない。**
- 勝利 c を 48 kHz / 16-bit / 0.7 秒の**ステレオ**にすると非圧縮データだけで
  **約 131 KB** となり、**1 ファイル 120 KB の上限と矛盾する。**
  モノラルなら**約 66 KB** で上限内に収まる。
- 容量とボイス処理を単純化できる。

**将来ステレオ版を制作する場合は、別仕様・別版として承認を得る。**

**WAV を選ぶ理由**

1. **短い効果音で開始位置を管理しやすい。**
2. **15 本合計で 800 KB 以内**に収まる。
3. **追加の圧縮フォールバックが不要。**
4. **対応対象ブラウザで PCM WAV を利用できる。**

**弱めた記述**【確】（初版の断定を次のとおり改める）

- ~~「WAV だけが同一フレーム開始を構造的に満たせる唯一の形式」~~
  → **WAV は開始位置を管理しやすいが、唯一の形式だとは言えない。**
- ~~MP3 は 576〜1105 サンプル、AAC-LC は 1024〜2112 サンプルの先頭パディングを持つ~~
  → **先頭パディングの有無と量はエンコーダ・コンテナ・デコーダの組み合わせで変わる。
    固定値をすべての実装へ一律に適用しない。**
  圧縮形式を採る場合は、**使う実装の組み合わせで先頭パディングを実測してから判断する。**

**圧縮形式は今回は採用しない。ただし将来の容量増加時に再検討できるものとして残す。**

**資産の合否条件**【確】（**統合 LUFS を一律の合否値にしない**）

| # | 条件 |
| --- | --- |
| 1 | **トゥルーピーク** ≤ −3.0 dBFS、かつ各イベントの個別上限以内 |
| 2 | **サンプルピーク**を記録する |
| 3 | **クリッピング 0** |
| 4 | **DC オフセット**が閾値以内 |
| 5 | **先頭無音** ≤ 2ms |
| 6 | **末尾無音** ≤ 30ms |
| 7 | **実時間**が各イベントの最大長以内 |
| 8 | **同一条件で測った active-region RMS** |
| 9 | **ゲーム内の相対ゲイン**（3-17-4 の基準ゲイン） |
| 10 | **実機での人間確認** |

**active-region の定義**
- 先頭と末尾の**完全無音を除く**
- **ピークから 40 dB 以内の区間**
- その区間の RMS を記録する
- **RMS は制作物間の比較値として使い、単独で人間の聞こえ方を証明しない**

**撤回した条件**【確】
- ~~すべての短い効果音を「統合ラウドネス −20 LUFS ±1」で一律に合否判定する~~
- ~~勝利 b だけ −18 LUFS ±1 とする~~

**理由**：提出音の多くは 70〜340ms である。EBU Mode の Momentary は 400ms、
Short-term は 3 秒であり、**短い単発効果音は統合 LUFS だけを同じ尺度の厳密な合否値として
比較するのに適さない。**短い無音や減衰尾の長さで値が大きく変わる。

**LUFS は情報値として測定・記録してよいが、400ms 未満の効果音では単独の合否条件にしない。**
**勝利 3 段を連結した全体など、十分な長さがある資料では参考値として扱える。**

**短い効果音の音量統一は、次の 3 つで行う。**
1. **資産のピーク／active-region RMS**
2. **ゲーム内の相対ゲイン**
3. **実機での人間確認**

### 7-4. 会話の設計方針【推】

**表示方式の候補**【推】

| 場面 | 候補 |
| --- | --- |

  人間評価が必要である。**
- **当面は文字会話を先に成立させる。**音声は追加可能な構造にするが、
  **収録・合成・採否は未決**【要】。
